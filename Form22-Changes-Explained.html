2The problem we started with

Part 2 - What we built

4The backend file, helper by helper

File: srv/extcalls/remoteCall4_form22.js (first called backend.js, renamed in step 8).

  1. Delete the mock deleted
    Removed mock.js, the live() switch and the mock import. Every call now goes to the real backend, like TAN.
  2. Connect and build URLs 
    const NS = 'com.sap.gateway.srvd.zsb_itemdetails.v0001'
const ext = () => cds.connect.to('ZSB_ITEMDETAILS0001')
const q = v => String(v).replace(/'/g, "''")
const item = k => `ZC_ITEMDETAILS(Kunnr='${q(k.Kunnr)}',invoice='${q(k.invoice)}',frameno='${q(k.frameno)}',engineno='${q(k.engineno)}')`
    ext() is the connection (destination BAS). item() builds the full item key an action needs in its URL. q doubles single quotes so a value cannot break the URL.
  3. getUser: the same rule as TAN 
    const getUser = req => {
  const user = req.user?.attr?.logonName || req.user?.name || req.user?.id
  if (!user || !/^[PD]/i.test(user)) return req.reject(403, 'Access denied: User is not recognized as a valid ID')
  return user
}
    Takes logonName first (in production the id can be a long UUID). If empty, or not starting with P or D, the call is refused with 403.
  4. auth: ask ABAP about the user fixed later 
    const auth = (service, req, lv_user) => service.tx(req).send({
  method: 'POST', path: `ZC_ITEMDETAILS/${NS}.checkUserAuth`,
  data: { is_authorized: false, change_visi: false, kunnr: '', name1: '', lv_user }
})
    Calls the backend action checkUserAuth. ABAP answers with is_authorized, change_visi, kunnr, name1. The false/empty values are only there because the backend action needs every field present. lv_user always comes from the session, never from the browser. The request body is not forwarded (see step 9).
  5. dealerOf: who may see what 
    const dealerOf = async (service, req) => {
  const user = getUser(req)
  if (!/^D/i.test(user)) return undefined
  const res = await auth(service, req, user)
  if (!res?.is_authorized || !res.kunnr) return req.reject(403, 'Access denied: User is not authorized for any dealer')
  return res.kunnr
}
    P user (internal): no restriction. D user (dealer): asks ABAP; not authorized or no dealer returned means 403, otherwise the backend's kunnr is used.
  6. wrap: error handling 
    const wrap = (tag, fn) => async req => {
  try { return await fn(req) }
  catch (error) {
    cds.log('form22').error(`[FORM22:${tag}] Execution failed: `, error.message)
    const s = error.status || error.statusCode || error.code // keep 403s from the user check
    return req.reject(Number.isInteger(s) && s >= 400 && s < 600 ? s : 400, error.message)
  }
}
    Every handler is wrapped: one log line with the handler name, and a real 4xx/5xx code (like our 403) is kept. Anything else becomes 400.
  7. read: reading data 
    export const read = wrap('read', async req => {
  const service = await ext()
  const kunnr = await dealerOf(service, req)
  if (kunnr && req.query.SELECT) {
    req.query.where(req.target.name.endsWith('ZC_ITEMDETAILS') ? { Kunnr: kunnr } : { kunnr })
  }
  return service.tx(req).run(req.query)
})
    For a D user a dealer filter is added before the query goes to the backend. The field is Kunnr on items and kunnr on the three value helps. A P user gets everything.
  8. changeFrame and printForm 
    const bound = (tag, action, data) => wrap(tag, async req => {
  const service = await ext()
  const kunnr = await dealerOf(service, req)
  const key = req.params[0]
  if (kunnr && key.Kunnr !== kunnr) return req.reject(403, 'Access denied: item belongs to another dealer')
  return service.tx(req).send({ method: 'POST', path: `${item(key)}/${NS}.${action}`, data: data(req) })
})
export const changeFrame = bound('changeFrame', 'changeFrame', req => req.data)
export const printForm   = bound('printForm',   'printForm',   () => ({}))
    A dealer can only act on his own items. This extra check does not exist in TAN; we added it so one dealer cannot print another dealer's form.
  9. checkUserAuth and getUserInfo 
    export const checkUserAuth = wrap('checkUserAuth', async req => auth(await ext(), req, getUser(req)))
export const getUserInfo   = wrap('getUserInfo',   async req => ({ userId: getUser(req) }))
    checkUserAuth is what the UI calls on start (user bound from the session, sent to ABAP as lv_user). getUserInfo returns the validated id, like TAN.

Part 3 - Verify and use

9Final check: what we found and fixed

At the end we re-read everything (and compared mta.yaml with TAN's) before declaring it done. Three problems showed up, all fixed.

Bug: fixed Change Frame for dealers would likely fail.
The dealer lookup copied the whole request body into the checkUserAuth call. For changeFrame that body holds matnr, frameno_in, engineno_in, so ABAP would get extra fields and probably reject the call.
Fix: removed ...req.data from auth(). The defaults already cover every required field.
Local run: fixed every request returned 403.
CAP's default test users (alice, bob) do not start with P or D, and there is no mock any more.
Fix: package.json now has [development] mocked users P12345 (internal) and D11685 (dealer), both with an empty password.
Deploy: fixed no connectivity service in mta.yaml.
We had set connectivity: true like TAN, but Form22's mta.yaml only bound db, destination and XSUAA. If BAS reaches S/4 through the Cloud Connector, production calls would fail.
Fix: added a hmcl_Form22-connectivity service (plan lite) and bound the srv module to it, the same as TAN.

Stale files cleaned

  • test.http: every request now sends a login header for P12345; the checkUserAuth example uses the local URL /checkUserAuth; the old "mock" wording is gone.
  • .vscode/launch.json: removed --with-mocks.

Checks done

CDS model compiles, remoteCall4_form22.js passes the syntax check, package.json and launch.json parse, and cds env shows the new local users loaded.

Not done: running against the real backend. The kind: "odata" setting was left as it was (TAN uses odata-v4); if backend calls fail, change that first.

11How to test it

  1. Run npm install once (for @sap/xssec).
  2. Make sure the BAS destination is reachable locally, then start with npm start or cds watch.
  3. Log in as P12345: lists show all dealers; Change / Select All / Deselect All show only if ABAP returns change_visi = true.
  4. Log in as D11685: lists show only the dealer ABAP returns for that user; trying another dealer's item gives 403.
  5. Try a user whose name does not start with P or D: expect 403.
  6. Use test.http for quick calls (replace the sample dealer, invoice and frame values with ones that exist in your system).
  7. Before deploy, run npm run build to rebuild the mtar so the new mta.yaml is picked up.
